# 控制与只读观测

输入：设备所有者、控制状态机、save/recognized 等回调、相机帧缓存、预览发布器、UI 读取逻辑与进程身份记录。输出：不争用设备的旁路结构、图像/状态元数据契约、日志归属及最小接线修改。

1. 保持相机/串口/动作设备的单一所有者。UI 读取受控快照，不能为显示再次打开相机，不能消费控制取帧游标，也不能绕过任务入口发动作。
2. 沿状态保存、识别图、动作阶段和退出逐项核对实际回调。接入独立入口时检查是否仍传递 save/recognized；继承状态机并不自动继承展示与日志。
3. 在同一快照中取得图像、来源帧号、时间和任务代际。只有对应 JPEG 实际发布后才提交其元数据；编码期间的新帧或状态变化不能给旧图贴新身份。
4. 以 PID、进程启动 ticks、boot ID、真实命令和运行会话绑定记录，防止 PID 重用或旧文件被识别为在线。UI 比较自己读取的同一状态快照的代际，并检查画面新鲜度。
5. 将原始相机旁路、PL 输出和模型输入分别标记。分类结果保留模型/帧/任务来源；SDK 写入完成只代表软件命令完成，不能当作物理抓取成功。

可改参数：发布频率、编码尺寸/质量、新鲜度窗口、输出目录、会话键和日志保留策略。复用时按实际进程/OS 身份机制适配；本项目的 `/proc` 检查不是跨平台实现。

失效条件：双设备所有者、旧输出目录混用、图像与元数据错配、源会话重启或过期画面。呈现明确离线/过期状态并保留原因，不伪造 LIVE。适用于自动化台架、相机仪器和机器人展示；不提供动作许可或机械安全认证。

检查建议：覆盖编码期间来源/代际变化、画面停滞、旧目录残留、源会话重启及 PID 重用；对照实际 JPEG、已发布元数据和 UI 所读状态，确认错配或过期时不显示 LIVE。执行范围按当前任务约定，结果保留所属图像与身份记录。
