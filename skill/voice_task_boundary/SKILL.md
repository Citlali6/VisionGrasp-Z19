# 语音任务边界

输入：实际语音来源、命令/语言映射、任务状态机、采集/滤波/ASR 代码、事件消息和所有缓存位置。输出：来源选择表、一次任务转换表、生产端确认协议，以及旧输入跨任务路径的修订。

1. 确认来源是串口命令编号还是 PCM。编号不能进入滤波器；同一任务只接纳选定来源。以部署记录核对标准口令与语言，不凭模块名称猜编号。
2. 列出唤醒有效期、启动、忙碌、取消和结束边界。保留准备、识别、播报完成、执行的业务次序；部分 ASR、任意文本或低置信度结果不直接触发动作。
3. 沿采集设备→内核/进程管道→PCM 块→滤波历史→ASR 未完成片段→网络事件→接收队列追踪缓存。接收端清队列或检查最后一块年龄，无法排除旧半句延后完成 ASR。
4. 需要丢弃忙碌输入时，在生产端建立可确认的清理/隔离边界。本项目中断旧读取、丢弃在途块、关闭旧采集与管道、清除滤波/ASR 状态并启动新采集，完成后才确认递增 boundary ID。其他采集协议可选择有依据的等效清理方式。事件保留其 ASR 调用所属边界；接收者拒绝旧边界，不重贴新标签。
5. 串行化边界请求；等待时不持有生产线程回调所需的锁。超时、断流和关闭必须唤醒等待者并明确失败，不能确认未完成重建。跨机器用生产端年龄和接收端本地计时，不相减两个主机的单调钟。

可改参数：标准口令/编号、语言、唤醒时限、置信度、PCM 格式、超时与边界编号范围。修改按实际设备协议和模型词典；本项目的“你好小亚”/编号1、启动92是来源实例，不是其他项目的默认值。

失效条件：来源混用、字典缺词、旧采集仍活跃、重建失败、边界不匹配或 ASR 片段年龄未知。返回明确原因；滤波设计与开放词汇识别效果不由本技能保证。可复用于声控仪器、服务机器人或其他一次事件任务。

检查建议：覆盖忙碌期半句在结束后才完成 ASR、读取或滤波在途时请求边界、重复/并发请求、超时和关闭；检查只在重建完成后确认、旧事件仍保留旧边界、失败不触发任务。执行范围按当前任务约定，结果附语音来源、缓存链与配置。

## 经验与证据对应

| 对应步骤 / 经验 | 具体记录 | 支持范围与未覆盖内容 |
|---|---|---|
| 1–2：按真实来源保留口令及一次任务语义 | [DOFBOT 验证](../../docs/VALIDATION.md)“DOFBOT 定稿版”的语音状态机覆盖及“单轮任务”行；[快速开始](../../docs/QUICKSTART.md)的实际唤醒/启动步骤 | 原串口任务有一次唤醒/启动、忙碌输入隔离和结束回等待的既有测试/现场反馈；支持旧编号事件路径，不证明 USB PCM、滤波或 ASR 边界有效 |
| 2：播报完成才进入既有类别动作 | 同一验证表“动作调用顺序”及原语音状态机覆盖，源码入口为[原 Session](../../robot/dofbot/standalone_voice.py) | 旧离线替身检查保持既有 SDK 次序；软件调用完成不是物理抓取成功率，也不能据此判断新 USB 事件时效 |
| 3–5：清理必须跨过旧 PCM、滤波历史与 ASR 未完成片段 | [协作案例二](../../report/ai_collaboration.md#case-voice-boundary)、[USB 生产端](../../host/app/voice/usb_pcm_pl.py)及[接口说明](../../fpga/audio_frontend/README.md) | 忙碌半句延后完成是源码路径发现；生产端重建、锁/等待及 boundary ID 确认见提交 8a76e84 |

本技能尚无独立运行、跨题目或跨板复用证据。USB 边界修订没有实测误触发收益，不能由旧串口记录推导其效果。
