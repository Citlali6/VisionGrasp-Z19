# Linux 相机 0：实现与验证

实现沿用已验证 FL0214/IMX214 传感器配置，在 Z19 Linux 中通过专用内核模块分配和管理 DMA 缓冲，再由采集程序和预览服务输出实时图像。

## 固定硬件契约

| 项目 | 已验证配置 |
|---|---|
| 平台 | XCZU19EG、Linux `5.4.0-xilinx-v2020.2`、AArch64 |
| 相机 | IMX214 / FL0214，相机 0，1920×1080 |
| 地址 | VDMA `0xA0060000`、Gamma `0xA0040000`、GPIO `0xA0080000` |
| I²C | `/dev/i2c-0`，传感器 `0x10`，镜头 `0x0c` |
| 缓冲 | 实测 0/1/2 三个 store 轮转；每帧 BGR 数据 |
| 兼容接口 | `ah_camera0`、`/dev/ah_camera0`，现有 `/opt/amazinghand/` 路径 |

原 XSA 的部分派生元数据写六帧，但已验证 bit 实际轮转三个 store；源码保留差异并按该 profile 防御处理。不要将此结论套到另一份 bit。CSI 初始化需要等待真实帧转换，短固定延迟不能替代就绪确认。

预览将完整 DMA 帧复制到普通内存，使用两个原生 JPEG 编码工作线程；复制窗口需不超过 30 ms，且源 store 不可正在写入。忙碌、过期或不安全帧被丢弃并计数。状态时间和序号持续前进；停流、故障或陈旧状态会关闭现有流并拒绝新图像请求。

## 实测结果

- 600 秒原采集记录含 599 个采样、33,333 次观察到的缓冲转换、零 DMA 错误样本，正常停止。转换频率不能作为无丢帧的传感器 FPS。
- 30 秒电脑接收检查解码 757 张不同的 1920×1080 JPEG，接收测量 **25.1607 fps**，无缺失已发布序号。该时段存在复制/忙碌丢弃，不等于所有传感器帧都被送达。
- 独立 60 秒正常采集发布 1,666 帧，零 DMA 错误和零复制/忙碌/过期丢弃，正常停止 DMA；此结果仅属于该时段。
- 故障验证覆盖停止、恢复、强制结束、陈旧帧及重新启动，返回状态和 DMA 停止情况保存在 JSON。
