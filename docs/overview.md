# 小亚智分：让分类成为一次可参与的操作

**面向绿色生活实践与嵌入式开发的语音视觉分拣工作站。**

一件物品被放入正确的分类容器之前，使用者需要完成识别、判断与投放。小亚智分围绕这一过程，把语音指令、视觉判断、分类反馈和机械执行组织成一个桌面工作站：使用者发起任务，系统识别目标并播报类别，机械臂完成固定工位投放，界面同步呈现任务过程。

项目以绿色生活实践为应用入口，把分类知识转化为可参与的实物交互。公众可以从一句口令开始，观察机器怎样判断、反馈和行动；开发者则可以沿着同一任务，理解图像处理、数字滤波、模型调用、接口通信和状态机怎样配合。

**听见指令，看清目标，让分类落到行动。**

## 从识别标签到完整交互

在课堂或展台上，组织者需要让参与者知道何时开始、机器识别了什么、接下来会发生什么，以及这一轮何时结束。只有识别标签，很难把这些环节连起来；相机、模型、语音和机械臂各自运行，也会增加演示与讲解的负担。

工作站以单次任务组织交互。参与者放置样本，发出唤醒和启动口令，观察类别反馈与投放动作，完成后让出工位。教师或工作人员可以围绕这条清楚的过程讲解分类依据，也可以引导参与者比较自己的判断与系统结果。

对开发者，这个任务提供了共同的应用背景：视频处理得到什么数据，模型怎样解释目标，候选规则接受什么条件，语音怎样改变任务状态，执行过程又怎样反映到界面。软件与硬件因此有一条可以逐层追踪的数据路径。

## 应用场景

### 校园绿色生活实践课

教师或活动志愿者在教室、科技活动室或校园体验台布置固定拾取位置，准备项目支持的样本或教具以及分类容器。学生先给出自己的分类判断，再将样本放到工位，移开手，说出“你好小亚”；听到“在的”后，再说“开始垃圾分拣”。

系统准备观察姿态，识别目标，播报物品与类别，随后执行对应的投放动作。窗口显示识别结果、播报内容和动作阶段，便于同组学生一起观察。教师可以在本轮结束后讨论：为什么属于这一类，自己的判断与系统反馈是否一致，样本的摆放和遮挡会怎样影响识别。

“先判断，再观察”是一种课堂活动组织方式。工作站提供可见的反馈与操作过程，教师负责问题设计和讲解，使分类知识、语音交互与机器人体验围绕同一个样本展开。

### 社区低碳体验与公共展示

在工作人员管理的社区活动台或公共展示区，短时参与者可以通过明确口令发起一次交互。工作人员准备支持的样本、保持相机和拾取位置，参与者放置样本、移开手，再按提示唤醒和启动。

窗口呈现识别、播报与执行阶段，旁观者可以跟随当前任务理解正在发生的操作。一次唤醒对应一次任务，本轮结束后重新唤醒，便于安排轮流体验。工作人员可结合播报结果说明分类规则，再为下一位参与者准备工位。

这一场景面向环保宣传、低碳体验与机器人展示，重点是简明的交互入口、可见的任务反馈和单件体验流程。

### 高校嵌入式与机器人实践

学生开发者和课程教师可以把同一个分拣任务拆成连续的工程问题：相机图像如何进入处理链，像素运算怎样在背压下保持帧身份，PCM 样本如何经过定点滤波，语义结果怎样成为候选条件，任务事件如何进入执行程序。

| 实践入口 | 可围绕源码开展的实验方向 |
|---|---|
| 视频数据流 | 阅读 RGB 校正、HSV、掩码、ROI 统计与一阶矩；设计固定输入，比较定点算子与参考计算 |
| 音频前端 | 阅读 DC、FIR 与可选软门，分析参数切换和样本握手，设计语音输入前端的对照实验 |
| AXI/FIFO 与 Linux 接口 | 跟踪寄存器事务、快照确认和 FIFO 流控，检查 C/RTL/Python 之间的字段对应 |
| PS 模型与候选规则 | 阅读模型输入、类别映射、坐标恢复和候选策略，分析同帧身份与连续帧条件 |
| VM 任务与展示 | 跟踪唤醒、识别、播报和执行状态，理解设备单一所有者、只读预览与事件记录 |

这些是可开展的实验方向。使用者可按[配置与部署](CONFIGURATIONS.md)准备匹配环境，再从[开发指南](DEVELOPMENT.md)选择检查入口。现用分拣应用、独立板端模块和四功能源码分别提供阅读起点，使一次任务既能用于观察交互，也能用于研究接口和控制逻辑。

### 小型回收服务点的单件交互工位（扩展方向）

面向有操作者辅助、固定物料和明确拾取位置的单件工位，可以考虑复用“识别—类别反馈—单次任务—状态展示”接口。操作者放入一个支持的物件，确认分类提示，再由适配后的执行机构完成后续动作。

该方向需要根据物料重新选择模型、相机、夹具与容器，建立工位标定、动作范围和独立验收方法；吞吐与执行能力由这些设计共同决定。当前项目为这一方向提供任务软件与感知接口，具体物料和新执行机构属于扩展设计。

## 一次任务怎样完成

现用 VM/DOFBOT 固定工位配置按以下顺序工作：

| 阶段 | 使用者或系统的操作 | 可观察的反馈 |
|---|---|---|
| 准备样本 | 使用者将支持的样本放到固定拾取位置并移开手 | 工位画面 |
| 唤醒与启动 | 使用者说“你好小亚”，等待“在的”，再说“开始垃圾分拣” | 唤醒回应、语音事件和任务状态 |
| 观察与识别 | 系统准备观察姿态，接受稳定出现的目标 | 实时画面、物品名称与投放类别 |
| 分类播报 | 系统播放对应物品与类别音频 | 播报声音和界面文案 |
| 抓取投放 | 播报完成后，SDK 执行既有类别动作 | 已下发动作的抓取、转运、释放和返回阶段 |
| 本轮结束 | 系统回到等待唤醒 | 下一轮从新唤醒开始 |

忙碌期间输入的命令不会积压为下一轮动作。未找到稳定目标时本轮结束；分类播报失败时不进入抓取。窗口从控制进程共享画面和状态，动作阶段表示指令进度，实际夹持和投放由操作者观察。

设备连接、启动与停止操作见[快速开始](QUICKSTART.md)。

## 技术怎样服务这条流程

**语音提出任务，视觉提供目标，候选规则约束执行，任务软件组织动作，界面呈现过程。**

现用演示由 VM 中的相机、检测模型、串口语音模块与 DOFBOT SDK 完成固定工位任务。开发者可以从[机械臂应用](../robot/dofbot/README.md)阅读状态机、播报完成门控、输入隔离、共享预览和进程管理。

Z19 PS/PL 四功能源码提供另一套感知与接口配置：PS 负责图像和 PCM 采集、CPU 模型、坐标解释、Vosk 及任务通信；PL 提供 RGB 校正、HSV/掩码、ROI/包围框/一阶矩、DC/FIR/可选软门和候选规则；可选 VM 客户端沿用既有任务与 SDK 动作。源码连接见 [system_pspl](../fpga/system_pspl/README.md)。

候选策略默认使用 `semantic_bbox`，依据同帧语义检测框的区域、面积和连续帧条件；需要指定颜色的工位可显式选择 `color_association`。像素坐标、颜色质心和相机标定后的平面坐标各有明确含义，机械臂采用固定拾取动作。
