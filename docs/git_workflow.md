# Git 与发布工作流

唯一开发仓库是 `Citlali6/VisionGrasp-Z19`。`main` 是唯一长期远端分支，所有更新通过短期分支和 PR 合并；完成后删除短期远端分支，阶段版本用标签与 Release 保存。

## 开始工作

```bash
git remote get-url origin
git status --short
git branch --show-current
git fetch origin
git worktree add -b feature/your-change ../visiongrasp-your-change origin/main
```

核对远程指向正确仓库后，在新工作树进行修改。原工作树的未提交内容、旧分支和归档保持不动。避免复用一个含他人修改的目录来完成无关任务。

主分支由 GitHub 分支规则与 PR 保护；仓库不依赖本地钩子。

## 提交与 PR

按当前任务授权选择检查，审阅 `git diff`、未跟踪文件和暂存差异。自动 CI 做标准 Git 文本、路径和冻结来源核对。只暂存本任务路径，使用聚焦提交，推送同名分支后正常创建以 `main` 为目标的 PR。

PR 说明应让未参与对话的读者理解：原问题、最终行为、涉及模块、验证结果和未覆盖的限制。文档清理不能改写旧实测结果；功能与依赖变化必须说明。

## 合并

检查目标分支、最终差异、冲突状态与所有适用检查后，由有权限的维护者通过 PR 合并。项目允许零强制外部审批；欢迎代码审阅，但不能虚构已经发生的 Review/Approve。自动化代理需有当前任务中的合并授权；已有授权不需重复索取。

合并后删除本任务的临时远端分支。历史分支清理按用户授权逐条核对当前 tip、整合关系和恢复引用；独有提交先建立远端归档标签，暂存、工作区和新增文件先备份，原本地工作树保留。删除前再次回读远端 SHA，出现并发变更只暂停对应分支。旧路线 PR 按归档关闭并保留讨论，不写成已合并。恢复依据以归档标签与备份为准。

不直接推送 `main`，不强推，不重写历史。不要使用 `--no-verify`、更换远程或修改保护规则绕过限制。仓库发布与硬件部署是独立操作：合并本身不授权机械臂运动、FPGA 加载或覆盖现用虚拟机。
